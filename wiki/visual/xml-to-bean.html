XML 한 줄이 Kotlin 객체가 되기까지

Spring 은 XML 을 읽자마자 객체를 만들지 않는다. 먼저 설계도를 이름으로 등록한다. 그다음 설계도대로 객체를 만든다. 아래에서 한 걸음씩 눌러 보며 확인한다.

01예시

XML 은 무엇을 만들지 적는다. Kotlin 은 그것을 이름으로 꺼내 쓴다. 이 페이지는 아래 두 파일만 쓴다.

beans.xml
<beans xmlns="http://www.springframework.org/schema/beans" ...>  <bean id="petStore" class="shop.PetStoreService">    <property name="accountDao" ref="accountDao"/>    <property name="maxItems" value="10"/>  </bean>  <bean id="accountDao" class="shop.JpaAccountDao"/></beans>
Shop.kt
package shopclass JpaAccountDaoclass PetStoreService {    lateinit var accountDao: JpaAccountDao    var maxItems: Int = 0}
  • id 는 빈 이름이다. class 는 만들 클래스의 전체 이름이다.
  • <property name="x"> 는 세터 setX(...) 를 부르라는 뜻이다. Kotlin 의 var 가 이 세터를 만든다.
  • ref 는 다른 빈의 이름이다. value 는 글자 그대로의 값이다.
  • 03 의 getBean<T>("이름") 은 Spring 이 Kotlin 용으로 주는 확장 함수다. getBean("이름", T::class.java) 를 부른다. spring-beans/src/main/kotlin/org/springframework/beans/factory/BeanFactoryExtensions.kt:40 @v7.0.10

02전체 그림

두 단계 사이에 설계도 저장소가 있다. 1단계는 저장소에 쓰기만 한다. 2단계는 저장소를 읽기만 한다.

    04실험 네 가지

    답을 열기 전에 03 의 체크 상자를 켜고 끝까지 눌러 본다. 예상과 다른 곳이 배운 곳이다.

    정의 순서를 뒤집으면 결과가 달라지나?

    만드는 순서만 바뀐다. 결과는 같다. Spring 은 등록한 순서대로 싱글톤을 만든다. ref 는 이름만 들고 있다가 필요할 때 getBean 을 부른다. 그래서 뒤에 정의한 빈도 참조할 수 있다.

    DefaultListableBeanFactory.java:1109 · :1315 @v7.0.10
    accountDao 가 prototype 이면 JpaAccountDao 객체는 몇 개 생기나?

    2개 생긴다. petStore 가 주입받을 때 1개, main 이 getBean 할 때 1개다. prototype 은 캐시에 넣지 않는다. 그래서 petStore.accountDao === dao 는 false 다.

    AbstractBeanFactory.java:346 @v7.0.10
    petStore 가 lazy-init 이면 언제 만드나?

    처음 getBean("petStore") 를 부를 때 만든다. 시작할 때는 건너뛴다. 설계도는 1단계에서 똑같이 등록된다.

    DefaultListableBeanFactory.java:1189 @v7.0.10
    ref 에 오타가 있으면 언제 실패하나?

    1단계는 통과한다. 리더는 그 이름의 빈이 있는지 확인하지 않는다. 2단계에서 getBean 이 설계도를 찾지 못할 때 실패한다. lazy-init 을 함께 켜면 실패가 main 의 getBean 줄까지 미뤄진다.

    BeanDefinitionValueResolver.java:365 · :375, DefaultListableBeanFactory.java:971 @v7.0.10

    05직접 만들 때

    이 페이지가 다루는 범위가 첫 구현의 범위다. <bean id class>, <property value|ref>, 싱글톤 캐시 세 가지다.

    생성자 주입, 자동 연결, 순환 참조, init-method, 확장 네임스페이스는 뺐다. 전체 기능 목록과 호출 흐름은 XML 로 빈 정의를 읽고 꺼내 쓰기 에 있다.

    이 페이지의 기준은 Spring 이다. summer-framework 가 같은 XML 을 읽게 되면, 같은 화면에 두 결과를 나란히 놓는다.
